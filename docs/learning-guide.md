# 项目学习指南 / Project Learning Guide

本指南对应 `low-cost-ai-agent-v1.6` 的当前代码。它按“请求怎样走”和“每层为何存在”来读项目，帮助从页面一路追到 Java 工具执行。

This guide describes the current `low-cost-ai-agent-v1.6` codebase. Follow the request path from the UI to Java tools to understand the role of each layer.

## 1. 先看整体请求链 / Start with the request flow

```text
浏览器 / Browser
  -> Spring Boot 静态页面与 API / static UI and APIs
  -> PostgreSQL 用户、文件、任务、额度 / users, files, tasks, quotas
  -> Redis 进度与临时 Excel 行集 / progress and temporary workbook rows
  -> Python FastAPI 接收任务 / receives task
  -> LangGraph 调用 LLM 并选择工具 / invokes the LLM and chooses tools
  -> Java Tool Registry 校验权限并执行 / validates permissions and executes
  -> ExcelAgentTools 生成结果文件 / creates the result workbook
  -> Spring Worker 完成任务，页面下载 / completes task; UI downloads the result
```

The browser never receives the internal Agent token and never calls the LLM or Java tool endpoint directly. The Java tool request carries task context supplied by Spring; tool arguments generated by the LLM cannot choose a different user or input file.

浏览器拿不到 Agent 内部令牌，也不会直接访问 LLM 或 Java 工具接口。Java 工具请求中的任务上下文由 Spring 提供；LLM 生成的工具参数不能替换用户或输入文件。

## 2. 按顺序阅读 / Suggested reading order

1. `backend/src/main/resources/static/index.html` — the sign-in form, upload flow, task polling, and result download. Follow the `taskForm` submit handler first.
2. `backend/src/main/java/com/excelai/task/TaskController.java` and `TaskService.java` — the API contract and ownership/plan/quota checks.
3. `backend/src/main/java/com/excelai/task/TaskWorker.java` — the asynchronous hand-off from Spring to LangGraph and task completion.
4. `backend/src/main/java/com/excelai/agent/AgentService.java` — the small HTTP bridge; notice it sends IDs, not filesystem paths.
5. `agent-service/app.py` and `agent-service/agent_graph.py` — FastAPI request handling and the LangGraph model/tool loop.
6. `agent-service/java_langgraph_tools.py` and `java_tool_client.py` — the model-facing schemas and HTTP proxy to Java.
7. `backend/src/main/java/com/example/agent/tool/controller/AgentToolController.java` and `ToolExecutionService.java` — service authentication, authorization, parameter validation, timeout, and audit.
8. `backend/src/main/java/com/excelai/excel/ExcelAgentTools.java` and `ExcelService.java` — the actual workbook operations.

建议按顺序阅读：先从页面的任务提交处理器开始，再跟随 Controller、Service、异步 Worker、LangGraph 和 Java 工具实现，最后看工具校验与数据访问层。

## 5. 为什么有些配置没有行内注释 / Why some configuration has no inline comments

`.env` is intentionally left untouched because it contains private credentials. `.env.example` documents the same variable names and safe placeholders. `opencode.json` is strict JSON, whose grammar has no comment syntax; adding `//` or `/* */` would make it invalid. Its `provider.ollama` section selects the OpenAI-compatible adapter, `options.baseURL` points at the local Ollama API, and the `models` entry names the model exposed to OpenCode.

由于 `.env` 保存了私密凭证，所以保持原样；对应变量已在 `.env.example` 解释。`opencode.json` 是严格 JSON，不支持 `//` 或 `/* */` 注释，写进去会导致配置无效。它的 `provider.ollama` 选择兼容接口，`options.baseURL` 指向本机 Ollama，`models` 声明 OpenCode 可选用的模型。

## 6. 数据存放原则 / Data ownership

- PostgreSQL stores durable users, plans, file metadata, tasks, and usage records.
- Redis stores task progress plus short-lived rows during workbook processing. `TaskDataService.rows()` returns a deserialized copy; after changing it, the tool must call `setRows()`.
- Workbooks are stored under the configured root. `FileStorageService` normalizes and bounds paths to prevent resolving outside that root.
- `TaskRepository.owned()` and `FileRepository.findOwned()` include the user ID in their queries; use these owner-scoped methods for user-facing data.

PostgreSQL 保存可持久恢复的业务记录；Redis 保存任务进度和处理中的短期行集；工作簿留在私有目录中。对用户数据的查询始终同时带上当前用户 ID。

## 7. MyBatis-Plus 持久层 / MyBatis-Plus persistence layer

`backend/src/main/java/com/excelai/persistence/entity` contains table-mapped entities, and `persistence/mapper` contains `BaseMapper` interfaces. `@MapperScan` registers those interfaces; `application.yml` enables underscore-to-camel-case mapping (for example, `user_id` to `userId`). The user, file, task, and plan repositories use MyBatis-Plus for ordinary inserts, lookups, and field updates while preserving their existing business-facing records.

`UsageService` retains its JDBC SQL for usage accounting because its database update/insert sequence has concurrency and atomicity requirements. `PlanRepository` also keeps the small read-only permission-count query for the composite-key `plan_tool_permission` table. This is a gradual persistence-layer migration; it does not change the Agent route/skill/tool flow.

`persistence/entity` 保存表映射实体，`persistence/mapper` 保存继承 `BaseMapper` 的接口；`@MapperScan` 负责注册 Mapper，`application.yml` 开启下划线转驼峰映射（例如 `user_id` 对应 `userId`）。用户、文件、任务和套餐仓储使用 MyBatis-Plus 完成常规插入、查询和字段更新，同时保持业务层原有 record 接口。

`UsageService` 继续使用 JDBC SQL，因为用量记账的更新/插入涉及并发和原子性要求。`PlanRepository` 也保留对复合键关系表 `plan_tool_permission` 的简单只读计数查询。这是渐进式持久层迁移，不改变 Agent 的 route/skill/tool 执行链路。

## 8. 教学示例与真实链路 / Demo code versus product path

`backend/.../DemoAgentTools.java`, `agent-service/tools/business_tools.py`, and `agent-service/tools/registry.py` are retained V1/demo examples. They return fake data or demonstrate a small local registry. The merged Excel SaaS path uses `ExcelAgentTools.java` through the Java registry and LangGraph proxy; it does not use the legacy Python registry.

`DemoAgentTools.java`、`business_tools.py` 和 `tools/registry.py` 是保留的 V1 演示代码；真实 Excel SaaS 请求使用 Java `ExcelAgentTools`，经 LangGraph 代理到 Java 注册表，不走旧 Python 注册表。
